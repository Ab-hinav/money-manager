## 2025-02-23 - Global Variable Initialization Race Condition
**Vulnerability:** Critical secrets (JWT_SECRET) were initialized in global variables using `os.Getenv` at package load time.
**Learning:** In Go, package `init` and global variable initialization happen *before* `main()` runs. Since `godotenv.Load()` was called in `main()`, the global variables captured the empty environment (or system env) *before* the `.env` file was loaded. This resulted in the application running with empty secrets (e.g., empty JWT key) when relying on `.env`, allowing authentication bypass.
**Prevention:** Avoid initializing secrets in global variables at the top level if they depend on runtime configuration loading (like `.env`). Use lazy-loading functions (getter pattern) or initialize globals explicitly after configuration loading is complete.
## 2025-05-10 - Fix JWT Algorithm Confusion Vulnerability
**Vulnerability:** The JWT parsing middleware (`AuthMiddleware`) in `backend/internal/api/middleware.go` did not explicitly verify the signing algorithm in the key function for `jwt.ParseWithClaims`.
**Learning:** This is a critical security vulnerability known as "Algorithm Confusion" or "None Algorithm" attack, where an attacker can modify the `alg` header of a JWT (e.g., to "none" or changing symmetric to asymmetric) and bypass authentication if the backend blindly trusts the header and returns the key. The `golang-jwt/jwt` library requires explicit type assertions of the `token.Method` inside the key callback to prevent this.
**Prevention:** Always verify that `token.Method` is of the expected type (e.g., `*jwt.SigningMethodHMAC` for HS256) inside the `ParseWithClaims` key function before returning the signing key.
